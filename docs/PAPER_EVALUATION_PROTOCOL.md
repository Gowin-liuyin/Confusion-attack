### 0.1 对照组与主张边界

研究方案是 A+B：A 为权重/词表混淆，B 为客户端密钥条件扰动。七个对照臂采用明文、AloePri-only、OSNIP-only、SentinelLMs、ObfusLM+、完整 InferDPT、DP-Forward。AloePri-only 是组件对照，当前可核实公开版本为技术报告，不能冒称正式发表；其他外部臂选正式发表版本，生成和分类能力不符的格子单列适用性。InferDPT 若只运行 RANTEXT 模块只能比较上传内容的隐私，不能冒充完整系统的效用。外部方案未集成前不编写结果。

正式发表参照：[SentinelLMs，AAAI 2024](https://ojs.aaai.org/index.php/AAAI/article/view/30136)、[ObfusLM，ACL 2025](https://aclanthology.org/2025.acl-long.58/)、[InferDPT，TDSC 2025](https://doi.org/10.1109/TDSC.2025.3550389)、[DP-Forward，CCS 2023](https://doi.org/10.1145/3576915.3616592)、[OSNIP，ICML 2026](https://proceedings.mlr.press/v306/cao26q.html)。如果以后要求连组件对照也全部正式发表，在本节明确替换决定；不要在另一份对比表另定名单。

论文按八组正文评测组织：KNN/EDNN、VMA-H、ISA、权重对齐及复合恢复、IMA 及迁移、跨请求链接、TFMA/SDA、上下文文本重构；输出侧另作统一泄漏审计。正文/附录按研究问题和信息条件安排，不按是否对我方有利安排。正式实验未达门槛必须标成未完成，不能用探针补位置。

## 1. 锁定部署与半诚实服务器

目标：恢复客户端私有 prompt 和客户端最终生成内容，提取其中的敏感实体，或判断不同请求中的观测是否源自相同 token。服务器按协议返回正确结果，但可存储其可见的完整记录，并离线联合分析任意请求、运行自己的模型、训练反演器及复算部署模型。只限制信息和交互权限，不以服务器算力低作为防护假设。

| 信息 | 默认主场景 S-public |
|---|---|
| 服务器模型 | 白盒：实际部署的全部权重、嵌入表、LM head、配置、公开 tokenizer 与词表；可离线前向、求梯度并查看每层激活及实际使用的 KV cache |
| 协议记录 | 实际收到的向量、掩码、位置、长度、顺序、会话或服务端可见用户标识、时间，以及服务器自身生成的 logits、协议中传输的输出 ID 和后续解码输入。轮换策略公开；主测保守地给轮换分组，不给 key 值。未知分组仅作敏感性分析 |
| 公开辅助信息 | 防御算法、编码器结构与训练配方、公开参考语料、可获得的同域分布、公开模型。当前开放权重部署的主场景应提供**准确匹配的原始底座权重**；如果项目公开了目标编码器权重，也应提供这些权重 |
| 客户端秘密 | 不给目标编码器的非公开权重、目标 key、词表置换、私有随机种子、客户端内存、真实 token/未上传明文和真值配对。秘密必须实际不可由发布文件、默认 seed 或请求元数据重建；不能靠给攻击代码隐藏一个公开文件维持假设 |
| 行为边界 | 不改模型、请求、响应、解码分支或换钥流程；不迫使目标客户端加密攻击者选择的文本，不窃取客户端秘密。允许用公开数据在攻击者自己的实例上离线生成配对；不能混入真实目标配对 |

另报三个分栏：S-deploy 仅持部署权重和真实可见记录（适用于原权重确实不可取得的部署）；S-encoder 加目标编码器权重但不给目标 key，测错钥、候选 key 搜索或替代实例适配；S-pair 给目标实例的明文—观测对，明确来源、比例、是否同 key。若编码器或配对在正常部署中就能取得，相应条件并入主场景。正确 key、真实置换、真实前缀和客户端解码明文仅作 oracle/正控。匹配权重对不等于配对用户请求，也不等于知道置换。

开跑前锁定代码版本、底座权重/词表校验值、服务端请求与返回格式、密钥来源/轮换及缓存行为。当前可运行演示逐步重编码并重传完整前缀，在客户端还原 logits 并采样；旧效用计划则假设只扰动 prompt、服务器用自身表生成后续 token。两者分别泄漏不同记录，延迟也不同。默认测当前完整协议；若改用另一种生产协议，隐私、效用、成本全部一起重测。正式实验的密钥和置换用秘密随机源产生，审计材料保存配置和结果，不公开正在受测的秘密种子。当前工件元数据指向 base，而部分历史命令写 Instruct 路径；以源工件和张量校验核实，不能仅凭路径名认定匹配或不匹配。

文献依据：[OSNIP §2.1、附录 D.1（ICML 2026）](https://proceedings.mlr.press/v306/cao26q.html) 给部署模型白盒、不给 key，编码器白盒和正确 key 单列；[AloePri §3.2、§5.1、§7.3、附录 D.1（技术报告）](https://arxiv.org/abs/2603.01499v2) 分析输入/输出、权重对齐、训练反演、长期词频，权重对齐实验有原始与部署权重；[ObfusLM §3.2、附录 C.2/E（ACL 2025）](https://aclanthology.org/2025.acl-long.58.pdf) 给部署权重和分布先验，并用攻击者自建实例训练；[Dong 等 §3（USENIX Security 2025）](https://www.usenix.org/system/files/usenixsecurity25-dong-tian.pdf) 明确半诚实服务器可保存状态供离线反演。AloePri 在此用于协议对齐，发表状态不与正式会议论文混列。

## 3. 效用与隐私绑定

- **主底座完整跑**：同一 checkpoint 和词表的明文、仅 A、仅 B、A+B，外部方案按适用任务同底座比较；需要原作者微调的基线按论文做训练适配，另给同等训练机会的明文参照。仅 B 必须用在干净底座上独立训练的编码器。第二底座至少复验关键隐私结论、全量 PPL/摘要以及预注册的完整下游任务；只跑同一家族两种大小，结论写跨规模。
- **正式效用套件**：主底座跑 OSNIP 的 MMLU、ARC-Easy、HellaSwag、PIQA、MNLI、SST-2、ANLI R1/R2/R3、WiC 全官方指定 split；加完整 QNLI 作分类基线公共锚。WikiText-2 完整 test，固定滑窗，记录有效计分 token 与边界规则；CNN/DailyMail 固定抽样 1,000 条官方 test，端到端生成，报 ROUGE-L 与 BERTScore。若主张中文、指令遵循、代码或数学，再加入对应完整 C-Eval、IFEval、HumanEval 或 GSM8K，不能拿探针代替。来源：[OSNIP §4/Tables 1–3](https://proceedings.mlr.press/v306/cao26q.html)、[AloePri §7](https://arxiv.org/abs/2603.01499v2)、[ObfusLM §6](https://aclanthology.org/2025.acl-long.58/)。
- **正式对比**：固定数据修订、模板、few-shot、截断、输出长度、解码参数和任务打分器。生成走真实协议；逐题保存明文与防御配对结果，报告绝对分数、差值及配对 95% CI。至少 3 个预注册防御工作点；可训练的核心方案使用至少 3 个独立训练 seed，固定随机方法复测独立随机种子。工作点与攻击超参只用验证集确定。比较同等效用下的最强可行攻击恢复率，并同时给完整曲线、相同样本上的区间及每格分母；不同机制的 ε 不直接横比。
- **效用正控与成本**：相同权重、数据和模板下，明文包装器与原生路径逐题一致（数值容差预注册）；论文明文结果是排查线索，不是要求所有不同配置硬对齐的门槛。训练时 PPL 或少量句子的 NLL 不代替正式任务效用。若写“效用基本不变”，须事先声明各主指标的最大可接受损失，且差值区间满足该界限；否则如实写折中。若写“在线开销低”，还需真实服务路径测 TTFT、TPOT、端到端延迟/吞吐、上下行字节、客户端成本、离线训练/导出，固定设备、并发和长度分布，报中位数及 P95。

## 4. 正式结果的通用验收

1. **正控有效且协议适用**：算法级正控验证可恢复实例，部署级正控在相同候选、数据、层与预算下跑；精确可解的 KNN/映射要求 Top-1 ≥99%，其他攻击采用预注册的原文锚或已知构造门槛，而非强迫所有任务接近 100%。再报先验/随机对照。未过正控、未达预算、未运行、前提不适用分开记。
2. **验证攻击已经吃满预算**：对学习、迭代和语料类攻击，验证集比较最后两档（预算至少翻倍或按文献档位），主要恢复指标仍提升超过 2 个百分点，或区间仍允许超过 2 点的增益，就加预算或明确标成未饱和；预先冻结测试集，不按测试结果挑模型、层或重启。攻击失败率和缺失值也要保留。
3. **指标对准隐私目标**：主要报告端到端原始 token Top-1、完整序列恢复、实体级 PII 恢复；Top-5/10、token F1、语义指标与候选覆盖作补充。未检出候选也留在主分母。跨 tokenizer 用字符对齐后的词/实体指标共同比较，模型自身的 token Top-k 单报。至少 2,000 次以独立 prompt、文档或会话为单位的配对 bootstrap；有重复 key 观察时保留聚类结构，另外报告跨训练 seed 波动。
4. **冻结可复查材料**：记录数据划分及哈希、模型及协议版本、攻击输入清单、超参/预算、每条结果、正控、运行失败与计算成本。明文答案、真实标签、密钥与置换只进打分端，不能用于构造攻击候选。主要比较报告同一效用工作点下验证集预定攻击的测试结果；同时公开各攻击结果，包括对我方最不利的结果。

### 8.3 基线接入、效用与效率冻结

- 每个防御适配器必须声明：输入/输出消息、公开/秘密资源、是否需要模型微调、client/server运行边界、支持的任务、训练代价、key/随机化机制、正式来源/代码commit/license/偏差。提供同一攻击者视图、配对评分接口、生成记录接口；不要为了接口统一而给文本方案虚构不存在的上传向量，也不能限制服务器读取其本来可见的ID/logits。
- **SentinelLMs、DP-Forward** 先复现作者原分类任务和算法。若没有通过“适配为 decoder 模型”的算法与数值验证，不能强行纳入同底座 LLM 生成；分类辅助表需在同一BERT基座上提供完整可比的我方实现及明文参照，否则只报适用性和原方案复现，不能宣称我方在该表胜出。**ObfusLM+** 按原方案做必要微调；**InferDPT** 同时保留扰动和本地提取两个模块，客户端耗时也计入；我方A工件若非完整原算法必须明确工程变体，A-only保持同工件消融标签。
- 基线搜索空间固定为公开原文/官方默认设置加隐私参数网格：DP/text机制 epsilon={1,3,8}（分别解释其隐私定义，不能跨机制直接比）；ObfusLM+ k={5,10,20}、epsilon={0.1,1,3}，未变化的增强参数沿用作者实现；SentinelLMs glide-reflection次数={1,5,10}。若原算法隐私定义/合法参数域不允许该网格，先在本协议记录准确来源并修订，禁止静默套用错误网格。A/B/AB 用8.2三档噪声并训练适配，不能为测试集选漂亮工作点。
- 主模型正式效用为第3节全部任务完整split，统一0-shot，任务模板/版本与指定split在manifest固定，MMLU不得事后为贴论文明文换5-shot。PPL完整WikiText-2 test，window=512、stride=256（按窗口实际目标索引计数，每个目标token最多计一次）；CNN/DM从官方test按公开split seed抽1,000文档，输入上限1,024 tokens（保留提示尾），max_new_tokens=256、greedy；ROUGE-L和固定roberta-large revision的BERTScore。3B跑同套；7B跑KNN/复合/链接/迁移核心隐私、完整MMLU/ARC-E/HellaSwag/PIQA/SST2/QNLI、完整PPL及1,000摘要。各底座模板版本分别固定，不假定base与instruct相同分数。
- 若宣称“效用基本不变”，预设非劣界限：分类每项绝对损失≤2个百分点、PPL比≤1.05、ROUGE-L及BERTScore绝对下降≤0.01，并要求相应95%区间支持。它们是主张门槛，不是删结果的理由。达不到仍完整报告折中，不为通过而改指标；弱明文接近随机时单独指出判别力不足。
- 效率固定同硬件/精度、输入长度{128,512,1024}×输出长度128（正常EOS及提前结束均记录）×并发{1,4,16}；每条件20次warm-up、200个计分请求、3轮独立运行，报告TTFT/TPOT/端到端中位数/P95、吞吐、上下行字节、client耗时/内存及offline训练导出。完整前缀重传的客户端采样路径不得只用服务端一次forward伪装端到端成本。

### 8.4 冻结与修改的边界

此处固定算法预算与候选网格，但真实数据revision、文件哈希、许可证、原算法未在正文给出的完整模型配置、硬件环境必须在预检manifest中核实并冻结。未填完整禁止正式启动；这是可验证依赖，不授权 agent 任意选低强度替代。正式配置至少绑定八臂×信息场景×模型×工作点×seed×攻击的数据和工件。每格不支持须给具体原因。

实施 agent 可在显式 `probe` 下使用更小fixture验证代码，不能改变以上 paper-v1 值、把资源阻塞变成低预算正式结果，或自行标注“完美/安全”。更新预算必须修改本节、说明证据并生成新的协议hash，历史结果保留原绑定。
