# 威胁模型修正：权重面攻击的前提分级（2026-11-07）

> 触发：主控质疑「你确定你的攻击前提是不知道秘密？」。本文件把**每个权重面数字用到什么输入**逐条摊开，
> 并给出修正后的分类。修正前的数字（99.6% / 94.1% / 0.5% / 1.0%）**不得**再作为 KW 主表结果引用。

## 0. 结论

1. **论文的 VMA/Gate-IA 数字低，是因为服务器只有"混淆后的权重"，没有干净权重配对。**
   我之前的 dense-mixing 链虽然不读 τ、不读 key、不读 `client_secret.pt`，但它需要
   **干净基座权重 + 混淆权重**这一对。按本项目部署（服务器只拿到 `model_server/`），
   那对权重本身就是秘密的一部分 → 该攻击属 **known-pair（KP 类）**，只能进附录/消融。
2. 更严重的是 **RowSort 两个数（0.5% / 1.0%）连 KP 都不是**：它们的构造 `Y = E_dep[perm[ref]]`
   用**真值置换**挑行，攻击者拿不到 → 只能算 known-secret 诊断。
3. C08 Gate-IA（94.1%）同样是**配对**攻击：`Avg(e W_gate)` 要两边模型才能对得上。
   已在 payload 里改成 `uses_known_pairs=true`、`main_table_eligible=false`。
4. **C01 KNN（stage-1 = 62.90%）不受影响**：它只用服务器自己那张部署侧嵌入表，不碰干净权重、
   不碰 τ，是真正的 KW/K0 结果。

## 2. 为什么"论文数字就该低"

AloePri 的 VMA/Gate-IA 在 α_e=1.0 / α_h=0.2 的工作点上报告 PIIRSR <3%：

- **只有混淆权重**时，攻击者没有"干净↔混淆"的对应关系，只能依赖**矩阵自身的不变量**
  （行范数、排序幅值、列统计的自洽性）。dense 变换 + 噪声把这些不变量打散 → 恢复失败；
- 一旦**给了干净权重配对**，`W' = W M` 变成可解线性系统（残差 0.0139 ≈ α_h），
  置换自然就被恢复。**这两个威胁模型差一个数量级，正是论文与我的数字差异的来源**；
- 我们的工件是 α*=0.2/0.01（比论文工作点噪声小 5–20 倍），所以同一攻击在它上面更强 —— 这与
  导向 §2.2「α 工作点不可直接对比、α* 下 VMA-W 会显著更高」的提醒一致。

## 5. 本轮同时修掉的实现问题

1. **复合链映射 bug**：`mapping[deployment_id]` 之前拿反混合表**自匹配**（返回自身行号→恒等映射），
   已改为"反混合行 → 查干净表"；后又改为**前向匹配**（`E_dep` 对 `E_clean @ M`），不做矩阵求逆。
2. **M 的病态**：4 层 q_proj 取中位数得 cond≈8e5（各层变换不同 + 方阵最小二乘精确解放大病态）；
   改为 q/k/v × 16 层（48 个提案）取中位数，cond≈17.5，并加条件数守卫（超过 1e4 退到最优单提案）。
3. **环境**：BLAS 线程未设置时 `1000×2048×128256` GEMM 只有 ~1 GFLOPS（>10 min）；显式设置
   `OPENBLAS_NUM_THREADS/OMP/MKL` 后 ~350 GFLOPS（1.5 s）。已固化进全部脚本。
4. **内存**：权重攻击不再载入两个 1B 模型（`load_models=False`，~3 GB 而非 ~10 GB），
   权重按张量从 safetensors 读。
